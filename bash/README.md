# Bash: справочник

[Главная](../README.md) · **Bash** · [Python](../python/README.md) · [Git](../git/README.md) · [Docker](../docker/README.md) · [Примеры](../examples/README.md) · [Источники](../SOURCES.md)

Шпаргалка по командной строке Bash и стандартным утилитам GNU. Минимальная версия: Bash 4.0 (`declare -A`, `${var^^}`). Проверено: 5.2.37 в Git Bash для Windows. Отличия Git Bash и WSL вынесены в отдельные разделы.

> [!WARNING]
> Строки с пометкой **⚠️ Опасно** могут безвозвратно удалить или перезаписать данные. В Bash нет корзины и нет «отменить». Прежде чем выполнять такую команду, посмотрите, на что она подействует: замените `rm` на `ls`, а `-delete` на `-print`.

## Навигация

| Команда | Назначение | Пример | Важные замечания |
|---|---|---|---|
| `pwd` | Показать текущий каталог | `pwd` | В Git Bash путь выглядит как `/c/Users/Sergey`, в WSL — `/home/sergey` или `/mnt/c/...` |
| `ls` | Список файлов | `ls -lah` | `-l` — подробно, `-a` — со скрытыми (`.git`, `.env`), `-h` — размеры в K/M/G |
| `ls -lt` | Сортировка по времени изменения | `ls -lt \| head -n 5` | `-r` переворачивает порядок, `-S` сортирует по размеру |
| `cd КАТАЛОГ` | Перейти в каталог | `cd ~/projects/app` | `cd` без аргументов ведёт в домашний каталог |
| `cd ..` | На уровень выше | `cd ../..` | `.` — текущий каталог, `..` — родительский |
| `cd -` | Вернуться в предыдущий каталог | `cd /tmp && cd -` | Печатает путь, в который вернулись |
| `pushd` / `popd` | Стек каталогов: зайти и вернуться | `pushd /etc && popd` | `dirs -v` показывает стек. Удобно в скриптах |
| `tree` | Дерево каталогов | `tree -L 2 -a` | Не всегда установлена (в Git Bash её нет). Замена: `find . -maxdepth 2` |
| `realpath` | Абсолютный путь | `realpath ./README.md` | Раскрывает символические ссылки |
| `basename` / `dirname` | Имя файла / путь к его каталогу | `basename /a/b/c.txt .txt` → `c` | В скриптах быстрее раскрытие `${path##*/}` и `${path%/*}` |

Специальные обозначения путей: `~` — домашний каталог, `.` — текущий, `..` — родительский, `/` — корень. Если путь начинается не с `/` и не с `~`, он относительный и отсчитывается от текущего каталога.

## Файлы и каталоги

| Команда | Назначение | Пример | Важные замечания |
|---|---|---|---|
| `touch` | Создать пустой файл или обновить время изменения | `touch notes.txt` | Содержимое существующего файла не меняется |
| `mkdir -p` | Создать каталог вместе с родителями | `mkdir -p src/app/utils` | С `-p` нет ошибки, если каталог уже есть |
| `cp` | Копировать файл | `cp config.yml config.yml.bak` | ⚠️ **Опасно:** молча перезаписывает файл назначения. `-i` спрашивает, `-n` никогда не перезаписывает |
| `cp -r` | Копировать каталог целиком | `cp -r src/ backup-src/` | `cp -a` дополнительно сохраняет права, владельца и время |
| `mv` | Переместить или переименовать | `mv old.txt new.txt` | ⚠️ **Опасно:** молча перезаписывает файл назначения. Используйте `mv -i` или `mv -n` |
| `rm` | Удалить файл | `rm -i temp.log` | ⚠️ **Опасно:** удаляет без корзины. `-i` спрашивает подтверждение на каждый файл |
| `rm -r` | Удалить каталог с содержимым | `rm -r build/` | ⚠️ **Опасно:** удаляет всё дерево безвозвратно |
| `rm -rf` | Удалить без вопросов и без ошибок для несуществующих файлов | `rm -rf -- "./dist"` | ⚠️ **Опасно:** самая разрушительная команда. Не пишите `rm -rf $VAR/`: при пустой переменной получится `rm -rf /`. Безопасный вариант: `rm -rf -- "${VAR:?}/"` |
| `rmdir` | Удалить пустой каталог | `rmdir empty-dir` | Безопасна: непустой каталог не удалит |
| `ln -s` | Символическая ссылка | `ln -s /opt/app/current app` | Порядок аргументов: сначала цель, потом имя ссылки. В Git Bash вместо ссылки по умолчанию создаётся копия |
| `stat` | Подробные сведения о файле | `stat README.md` | Размер, права, время доступа и изменения |
| `file` | Определить тип файла по содержимому | `file script.sh` | Покажет `with CRLF line terminators`, если в файле окончания строк Windows |
| `du -sh` | Размер каталога | `du -sh node_modules` | `du -h --max-depth=1 .` показывает размеры подкаталогов |
| `df -h` | Свободное место на дисках | `df -h .` | С путём показывает только раздел, где лежит этот путь |
| `tar -czf` | Упаковать в `.tar.gz` | `tar -czf backup.tar.gz project/` | ⚠️ **Опасно:** архив с тем же именем перезапишется без вопросов |
| `tar -tzf` | Посмотреть содержимое архива | `tar -tzf backup.tar.gz` | Ничего не распаковывает; полезно перед `-x` |
| `tar -xzf` | Распаковать | `tar -xzf backup.tar.gz -C restore/` | ⚠️ **Опасно:** перезаписывает одноимённые файлы в целевом каталоге. Каталог для `-C` должен существовать |

Подстановки имён файлов (glob): `*` — любые символы, `?` — один символ, `[abc]` — один из перечисленных, `{a,b}` — перечисление (`cp file.{txt,bak}`). Glob раскрывает сама оболочка до запуска команды. Если совпадений нет, шаблон передаётся команде как есть.

Пример — проверяем шаблон перед удалением:

```bash
ls -- *.tmp      # 1. смотрим, что попадает под шаблон
rm -i -- *.tmp   # 2. удаляем с подтверждением
```

`--` означает «дальше только имена файлов». Без него файл с именем `-rf` будет воспринят как опция.

| `tail -f` | Следить за дописыванием файла | `tail -f /var/log/syslog` | `-F` переоткрывает файл после ротации логов. Выход — `Ctrl+C` |

## Поиск

| Команда | Назначение | Пример | Важные замечания |
|---|---|---|---|
| `find . -name` | Найти файлы по имени | `find . -name "*.log"` | Шаблон обязательно в кавычках, иначе его раскроет оболочка. `-iname` — без учёта регистра |
| `find -type` | Только файлы (`f`) или каталоги (`d`) | `find src -type d -name "__pycache__"` | `-maxdepth 2` ограничивает глубину и ставится перед остальными условиями |
| `find -mtime` / `-mmin` | По времени изменения | `find . -type f -mtime -1` | `-1` — менее суток назад, `+30` — более 30 суток. `-mmin` — в минутах |
| `find -size` | По размеру | `find . -type f -size +100M` | Единицы: `k`, `M`, `G` |
| `find -not` / `-path` | Исключить путь | `find . -name "*.py" -not -path "./.venv/*"` | Для больших деревьев быстрее `-prune`: `find . -path ./.venv -prune -o -name "*.py" -print` |
| `find -exec ... {} +` | Выполнить команду для найденного | `find . -name "*.sh" -exec chmod +x {} +` | Вариант с `+` передаёт файлы пачкой (быстрее), с `\;` — по одному |
| `find -delete` | Удалить найденное | `find /tmp/app -name "*.tmp" -mtime +7 -delete` | ⚠️ **Опасно:** удаляет без подтверждения. Сначала запустите ту же команду с `-print` вместо `-delete`. `-delete` должен стоять последним |
| `find -print0 \| xargs -0` | Безопасно передать имена с пробелами | `find . -name "*.txt" -print0 \| xargs -0 wc -l` | Без `-print0`/`-0` имена с пробелами разобьются на части |
| `grep "текст" файл` | Найти строки по шаблону | `grep "ERROR" app.log` | Код возврата: 0 — найдено, 1 — не найдено, 2 — ошибка. Удобно в `if` |
| `grep -rn` | Рекурсивно, с номерами строк | `grep -rn "TODO" src/` | `-I` пропускает бинарные файлы |
| `grep -i` / `-v` / `-w` | Без регистра / инверсия / целое слово | `grep -v "^#" config.ini` | `-v` выводит строки, которые не совпали |
| `grep -l` / `-c` | Только имена файлов / количество совпадений | `grep -rl "password" .` | `-c` считает строки, а не вхождения |
| `grep -E` | Расширенные регулярные выражения | `grep -E "^(GET\|POST) " access.log` | `+`, `?`, `\|`, `()` работают без экранирования |
| `grep --include` | Искать только в файлах по маске | `grep -rn --include="*.py" "import os" .` | `--exclude-dir=.git` пропускает каталог |
| `grep -A/-B/-C N` | Показать контекст вокруг совпадения | `grep -C 3 "Traceback" app.log` | After, Before, Context — строки после, до и с обеих сторон |
| `command -v` | Где находится команда и есть ли она | `command -v docker` | В скриптах надёжнее, чем `which`. Возвращает 1, если команды нет |
| `type` | Что это: программа, алиас, функция или встроенная команда | `type cd ll python` | Объясняет, почему команда ведёт себя неожиданно |
| `history \| grep` | Найти команду в истории | `history \| grep docker` | `!123` повторяет команду под номером 123. Интерактивный поиск — `Ctrl+R` |

Если установлен [ripgrep](https://github.com/BurntSushi/ripgrep), используйте `rg "текст"`: он быстрее и по умолчанию учитывает `.gitignore`.

## Процессы и задания

| Команда | Назначение | Пример | Важные замечания |
|---|---|---|---|
| `ps aux` | Все процессы системы | `ps aux \| grep python` | В выводе будет и сама строка `grep`. Чище: `pgrep -af python` |
| `pgrep -af` | Найти PID по имени или командной строке | `pgrep -af "uvicorn"` | `-a` показывает полную командную строку, `-f` ищет по ней |
| `top` / `htop` | Интерактивный монитор | `top` | В `top`: `P` — сортировка по CPU, `M` — по памяти, `q` — выход. `htop` нужно установить |
| `команда &` | Запустить в фоне | `sleep 60 &` | `$!` хранит PID последнего фонового процесса |
| `jobs -l` | Фоновые задания текущей оболочки | `jobs -l` | Задания привязаны к терминалу: в другом окне их не видно |
| `Ctrl+Z`, `bg`, `fg` | Приостановить, продолжить в фоне, вернуть на передний план | `fg %1` | `%1` — номер задания из `jobs` |
| `nohup ... &` | Процесс не завершится при закрытии терминала | `nohup ./server.sh > server.log 2>&1 &` | Без перенаправления вывод попадёт в `nohup.out` |
| `kill PID` | Вежливо попросить процесс завершиться (SIGTERM) | `kill 12345` | Процесс успевает сохранить данные и закрыть соединения |
| `kill -9 PID` | Убить принудительно (SIGKILL) | `kill -9 12345` | ⚠️ **Опасно:** процесс не успевает сохранить данные, возможны повреждённые файлы. Только если `kill` не помог |
| `pkill -f` | Завершить процессы по шаблону | `pkill -f "python app.py"` | ⚠️ **Опасно:** шаблон может совпасть с чужими процессами. Сначала проверьте тем же шаблоном через `pgrep -af` |
| `wait` | Дождаться фоновых процессов | `cmd1 & cmd2 & wait` | `wait $pid` возвращает код завершения этого процесса |
| `time` | Измерить время выполнения | `time ./build.sh` | `real` — по часам, `user`/`sys` — процессорное время |
| `timeout` | Ограничить время работы | `timeout 10 curl https://example.com` | При превышении возвращает код 124 |
| `sleep` | Пауза | `sleep 2` | Можно указывать дробные секунды: `sleep 0.5` |
| `ss -ltnp` | Какие порты слушаются (Linux, WSL) | `ss -ltnp \| grep :8000` | Чтобы видеть чужие процессы, нужен `sudo`. Альтернатива: `lsof -i :8000` |
| `free -h` | Использование памяти (Linux, WSL) | `free -h` | В Git Bash нет: используйте Диспетчер задач или `systeminfo` |

Сигналы, которые нужно знать: `SIGINT` (2) — `Ctrl+C`; `SIGTERM` (15) — `kill` по умолчанию; `SIGKILL` (9) — нельзя перехватить; `SIGHUP` (1) — закрылся терминал, а демоны часто воспринимают его как команду перечитать конфигурацию.

## Права доступа

Вывод `ls -l` выглядит как `-rwxr-x--- 1 sergey dev 1024 Nov 9 10:00 deploy.sh`:

- первый символ — тип: `-` файл, `d` каталог, `l` символическая ссылка;
- дальше три тройки `rwx`: владелец (`u`), группа (`g`), остальные (`o`);
- `r` — чтение, `w` — запись, `x` — выполнение для файла или вход в каталог.

| Число | Права | Типичное применение |
|---|---|---|
| `644` | `rw-r--r--` | Обычные файлы |
| `755` | `rwxr-xr-x` | Скрипты и каталоги |
| `600` | `rw-------` | Секреты: `~/.ssh/id_ed25519`, `.env` |
| `700` | `rwx------` | Личные каталоги, например `~/.ssh` |

Цифра — сумма: `r` = 4, `w` = 2, `x` = 1. Например, `rwx` = 7, `r-x` = 5.

| Команда | Назначение | Пример | Важные замечания |
|---|---|---|---|
| `chmod +x` | Сделать файл исполняемым | `chmod +x deploy.sh` | После этого скрипт запускается как `./deploy.sh` |
| `chmod ЧИСЛО` | Задать права числом | `chmod 600 ~/.ssh/id_ed25519` | SSH откажется работать с ключом, который могут читать другие |
| `chmod u+x,g-w,o-r` | Изменить права символически | `chmod g+w shared.txt` | `u`/`g`/`o`/`a` и `+`/`-`/`=` |
| `chmod -R` | Рекурсивно | `chmod -R u+rwX project/` | ⚠️ **Опасно:** `chmod -R 777` открывает всё всем, а без заглавной `X` даёт право выполнения обычным файлам. Права каталогов и файлов лучше менять раздельно через `find -type d` и `find -type f` |
| `chown` | Сменить владельца | `sudo chown sergey:sergey file.txt` | ⚠️ **Опасно:** `chown -R` по системным путям может сломать систему. Обычно нужен `sudo` |
| `id` / `whoami` / `groups` | Кто я и в каких группах | `id` | После добавления в группу (`usermod -aG docker $USER`) нужно перелогиниться |
| `umask` | Права по умолчанию для новых файлов | `umask` → `0022` | `0022` означает, что новые файлы получают 644, каталоги — 755 |
| `sudo команда` | Выполнить от имени root | `sudo apt update` | ⚠️ **Опасно:** у root нет ограничений. Не запускайте через `sudo` скрипты из интернета, не прочитав их |
| `sudo -l` | Что мне разрешено через sudo | `sudo -l` | Полезно на чужих серверах |

## Пайпы и перенаправления

У каждого процесса три стандартных потока: `stdin` (0), `stdout` (1) и `stderr` (2).

| Синтаксис | Назначение | Пример | Важные замечания |
|---|---|---|---|
| `a \| b` | stdout команды `a` подаётся на stdin команды `b` | `ls -1 \| wc -l` | stderr через пайп не идёт. Чтобы передать и его: `a 2>&1 \| b` или `a \|& b` |
| `> файл` | Записать stdout в файл | `echo "hello" > out.txt` | ⚠️ **Опасно:** файл обнуляется до запуска команды. `set -o noclobber` запрещает перезапись, `>\|` обходит этот запрет |
| `>> файл` | Дописать в конец файла | `date >> run.log` | Файл создаётся, если его нет |
| `2> файл` | Записать stderr в файл | `find / -name x 2> errors.txt` | `2>/dev/null` — выбросить ошибки |
| `> файл 2>&1` | stdout и stderr в один файл | `./build.sh > build.log 2>&1` | Порядок важен: `2>&1 > file` отправит stderr на экран |
| `&> файл` | То же, короче (только Bash) | `./build.sh &> build.log` | В `sh` (dash) не работает |
| `< файл` | Подать файл на stdin | `wc -l < data.csv` | |
| `<<EOF ... EOF` | Here-document: многострочный ввод | см. пример ниже | `<<'EOF'` в кавычках отключает подстановку переменных внутри |
| `<<< "строка"` | Here-string | `grep -c a <<< "banana"` | Удобная замена для `echo "строка" \| команда` |
| `tee` | Вывести на экран и записать в файл | `./test.sh 2>&1 \| tee test.log` | ⚠️ **Опасно:** без `-a` перезаписывает файл |
| `xargs` | Превратить строки stdin в аргументы | `cat urls.txt \| xargs -n 1 curl -sO` | `-n 1` — по одному аргументу, `-P 4` — 4 параллельных процесса, `-0` — для `find -print0` |
| `$(команда)` | Подставить вывод команды | `echo "Сегодня $(date +%F)"` | Старая форма в обратных кавычках хуже читается и плохо вкладывается |
| `<(команда)` | Подставить вывод как файл | `diff <(sort a.txt) <(sort b.txt)` | Только Bash |
| `a && b` | Выполнить `b`, только если `a` успешна | `mkdir -p build && cd build` | |
| `a \|\| b` | Выполнить `b`, только если `a` завершилась ошибкой | `cd /app \|\| exit 1` | |
| `a ; b` | Выполнить по очереди, независимо от результата | `make clean; make` | |
| `/dev/null` | «Чёрная дыра» | `command -v git > /dev/null` | Чтение из `/dev/null` даёт пустой ввод |

```bash
cat > hello.txt <<EOF
Пользователь: $USER
Каталог: $(pwd)
EOF
```

Код возврата пайпа по умолчанию равен коду **последней** команды. `false | true` считается успехом. Включите `set -o pipefail`, чтобы ошибка в любом звене делала весь пайп неуспешным. Коды всех звеньев последнего пайпа лежат в массиве `"${PIPESTATUS[@]}"`.

## Обработка текста в конвейере

| Команда | Назначение | Пример | Важные замечания |
|---|---|---|---|
| `sort` | Сортировка строк | `sort names.txt` | `-n` — числовая, `-r` — обратная, `-h` — по размерам вида `1K`/`2M`, `-u` — без повторов |
| `sort -k` / `-t` | Сортировка по полю | `sort -t, -k3,3n data.csv` | `-k3,3` — только третье поле. `-k3` означает «с третьего поля до конца строки» |
| `uniq` | Убрать **соседние** повторы | `sort ips.txt \| uniq` | Без предварительного `sort` дубликаты в разных местах останутся |
| `uniq -c` | Посчитать повторы | `sort ips.txt \| uniq -c \| sort -rn` | Классический приём «топ-N» |
| `cut` | Вырезать поля или символы | `cut -d: -f1 /etc/passwd` | Не понимает кавычки CSV. Для сложного CSV используйте Python |
| `tr` | Заменить или удалить символы | `tr 'a-z' 'A-Z' < f.txt` | `tr -d '\r'` удаляет CR из файлов Windows |
| `sed 's/a/b/g'` | Найти и заменить | `sed 's/http:/https:/g' links.txt` | Выводит результат в stdout, исходный файл не трогает |
| `sed -i` | Заменить прямо в файле | `sed -i.bak 's/DEBUG=1/DEBUG=0/' .env` | ⚠️ **Опасно:** изменяет файл на месте. С `-i.bak` сохраняется копия. На macOS синтаксис другой: `sed -i '' ...` |
| `sed -n 'X,Yp'` | Вывести диапазон строк | `sed -n '10,20p' app.log` | |
| `awk '{print $N}'` | Вывести поле N (разделитель — пробелы) | `awk '{print $1, $9}' access.log` | `$0` — вся строка, `NF` — число полей, `$NF` — последнее поле |
| `awk -F` | Задать разделитель | `awk -F, '$3 > 100 {print $1}' data.csv` | Можно задавать условия и считать суммы: `awk '{s+=$2} END {print s}'` |
| `column -t` | Выровнять по колонкам | `mount \| column -t` | `-s,` задаёт разделитель |
| `paste` | Склеить строки | `paste -sd, list.txt` | Превращает столбец в строку через запятую |
| `printf` | Форматированный вывод | `printf '%-10s %5d\n' "file" 42` | Предсказуемее `echo` для `-n`, `\t` и строк, начинающихся с `-` |

Готовый пример с пайпами: [`examples/bash/log_stats.sh`](../examples/bash/log_stats.sh) считает топ IP-адресов и коды ответов в access-логе.

## Переменные и окружение

| Синтаксис | Назначение | Пример | Важные замечания |
|---|---|---|---|
| `VAR=значение` | Присвоить переменную | `name="Сергей"` | Вокруг `=` не должно быть пробелов. `name = x` — это запуск команды `name` |
| `"$VAR"` / `"${VAR}"` | Получить значение | `echo "Привет, ${name}!"` | Почти всегда берите в двойные кавычки, иначе значения с пробелами разобьются на части |
| `'...'` и `"..."` | Одинарные кавычки — буквально, двойные — с подстановками | `echo '$HOME'` и `echo "$HOME"` | Внутри одинарных кавычек ничего не раскрывается |
| `export VAR` | Передать переменную дочерним процессам | `export API_URL=http://localhost:8000` | Без `export` переменную видит только текущая оболочка |
| `VAR=x команда` | Переменная только для одной команды | `LANG=C sort file.txt` | В текущей оболочке переменная не появится |
| `env` / `printenv` | Показать окружение | `printenv PATH` | `env -i команда` запускает команду с пустым окружением |
| `unset VAR` | Удалить переменную | `unset API_URL` | |
| `readonly` / `local` | Константа / локальная переменная функции | `local count=0` | `local` работает только внутри функции |
| `${VAR:-по_умолчанию}` | Значение по умолчанию, если переменная пуста или не задана | `port="${PORT:-8000}"` | Саму переменную не меняет. `${VAR:=x}` ещё и присваивает |
| `${VAR:?сообщение}` | Ошибка, если переменная пуста | `rm -rf -- "${BUILD_DIR:?не задан}/"` | Главная защита от `rm -rf /` |
| `${#VAR}` | Длина строки | `echo "${#name}"` | |
| `${VAR#шаблон}` / `${VAR##шаблон}` | Убрать префикс (кратчайший / длиннейший) | `f=a/b/c.tar.gz; echo "${f##*/}"` → `c.tar.gz` | |
| `${VAR%шаблон}` / `${VAR%%шаблон}` | Убрать суффикс | `echo "${f%.gz}"` → `a/b/c.tar` | `${f%%.*}` убирает всё после первой точки |
| `${VAR/a/b}` / `${VAR//a/b}` | Заменить первое / все вхождения | `p="a-b-c"; echo "${p//-/_}"` → `a_b_c` | |
| `${VAR^^}` / `${VAR,,}` | В верхний / нижний регистр | `echo "${name^^}"` | Bash 4+. Не работает в системном Bash 3.2 на macOS. Для кириллицы нужна UTF-8-локаль (см. [Git Bash в Windows](#git-bash-в-windows)) |
| `$(( выражение ))` | Целочисленная арифметика | `echo $(( (5 + 3) / 2 ))` → `4` | Дробные числа не поддерживаются. Для них есть `awk` или `bc` |
| `arr=(a b c)` | Массив | `echo "${arr[1]}" "${#arr[@]}"` | Индексы с 0. Перебор: `for x in "${arr[@]}"` |
| `declare -A` | Ассоциативный массив | `declare -A port=([web]=80 [db]=5432)` | Bash 4+. Ключи: `"${!port[@]}"` |

Специальные переменные:

| Переменная | Значение |
|---|---|
| `$0` | Имя скрипта |
| `$1` … `$9`, `${10}` | Позиционные аргументы |
| `$#` | Количество аргументов |
| `"$@"` | Все аргументы, каждый отдельным словом. Используйте именно эту форму |
| `"$*"` | Все аргументы одной строкой |
| `$?` | Код возврата последней команды (0 — успех) |
| `$$` | PID текущей оболочки |
| `$!` | PID последнего фонового процесса |
| `$PWD`, `$HOME`, `$USER`, `$PATH` | Текущий каталог, домашний каталог, пользователь, пути поиска программ |

Чтобы переменные и алиасы сохранялись между сессиями, добавьте их в `~/.bashrc` и примените изменения командой `source ~/.bashrc`:

```bash
export PATH="$HOME/.local/bin:$PATH"   # добавить каталог в начало PATH
alias ll='ls -lah'
```

## Скрипты

Минимальный надёжный каркас скрипта:

```bash
#!/usr/bin/env bash
set -Eeuo pipefail   # выход при ошибке, ошибка при неизвестной переменной, ошибки внутри пайпов

main() {
  local target="${1:?Использование: $0 КАТАЛОГ}"
  [[ -d "$target" ]] || { echo "Нет каталога: $target" >&2; exit 1; }
  echo "Файлов: $(find "$target" -type f | wc -l)"
}

main "$@"
```

Полный шаблон с разбором опций через `getopts`, `trap` и временным каталогом: [`examples/bash/safe_script_template.sh`](../examples/bash/safe_script_template.sh).

| Конструкция | Назначение | Пример | Важные замечания |
|---|---|---|---|
| `#!/usr/bin/env bash` | Shebang: каким интерпретатором запускать | первая строка файла | `#!/bin/sh` — это не Bash: массивы и `[[ ]]` там не работают |
| `chmod +x` + `./script.sh` | Запуск как программы | `./deploy.sh` | Альтернатива без прав на выполнение: `bash deploy.sh` |
| `set -e` | Завершить скрипт при первой ошибке | `set -e` | Не срабатывает внутри `if`, `&&`, `\|\|`. Подробнее — в [частых ошибках](#частые-ошибки) |
| `set -u` | Ошибка при обращении к незаданной переменной | `set -u` | Для необязательных переменных пишите `${VAR:-}` |
| `set -o pipefail` | Ошибка в любом звене пайпа | `set -o pipefail` | |
| `set -x` / `bash -x` | Трассировка: печатать каждую команду | `bash -x script.sh` | Лучший способ понять, что реально выполняется |
| `bash -n` | Проверить синтаксис без запуска | `bash -n script.sh` | |
| `if [[ ... ]]; then` | Условие | `if [[ -f .env ]]; then source .env; fi` | `[[ ]]` безопаснее `[ ]`: пустые переменные не ломают выражение |
| `case` | Выбор по шаблону | см. пример ниже | Каждая ветка заканчивается `;;` |
| `for x in ...` | Цикл по списку | `for f in *.csv; do wc -l "$f"; done` | Если файлов нет, в `f` окажется сам шаблон `*.csv`. Защита: `shopt -s nullglob` |
| `for ((i=0; i<5; i++))` | Цикл со счётчиком | `for ((i=1; i<=3; i++)); do echo "$i"; done` | Или `for i in {1..3}` |
| `while read` | Построчное чтение | `while IFS= read -r line; do echo "$line"; done < file.txt` | `IFS=` сохраняет пробелы по краям, `-r` — обратные слэши |
| `функция() { ... }` | Объявить функцию | `greet() { echo "Привет, $1"; }` | Аргументы функции — `$1`, `$2`… `return N` задаёт код возврата 0–255. Данные возвращают через `echo` и `$(...)` |
| `exit N` | Завершить скрипт с кодом | `exit 1` | 0 — успех, 1 — общая ошибка, 2 — неверное использование |
| `trap '...' EXIT` | Выполнить код при выходе | `trap 'rm -rf -- "$tmp"' EXIT` | Срабатывает и при ошибке, и при `Ctrl+C`. Идеально для очистки |
| `mktemp` / `mktemp -d` | Безопасный временный файл или каталог | `tmp="$(mktemp -d)"` | Не придумывайте имена вида `/tmp/myfile` сами |
| `getopts` | Разбор коротких опций | см. шаблон в `examples/` | Длинные опции (`--name`) придётся разбирать через `case` и `shift` |
| `source` / `.` | Выполнить файл в текущей оболочке | `source .venv/bin/activate` | Переменные из файла остаются в текущей оболочке |
| `read -rp` | Спросить пользователя | `read -rp "Продолжить? [y/N] " ans` | Пример подтверждения ниже |

Операторы проверок внутри `[[ ]]`:

| Оператор | Истинно, если |
|---|---|
| `-e путь` / `-f путь` / `-d путь` | Путь существует / это обычный файл / это каталог |
| `-r` / `-w` / `-x путь` | Есть право чтения / записи / выполнения |
| `-s файл` | Файл существует и не пустой |
| `-z "$s"` / `-n "$s"` | Строка пустая / непустая |
| `"$a" == "$b"` / `!=` | Строки равны / не равны. Справа можно указать шаблон: `[[ $f == *.txt ]]` |
| `"$s" =~ регулярка` | Совпадение с регулярным выражением. Группы попадают в `BASH_REMATCH`. Регулярку не берите в кавычки |
| `$a -eq $b`, `-ne`, `-lt`, `-le`, `-gt`, `-ge` | Сравнение **чисел**. Для чисел также удобно `(( a < b ))` |
| `!`, `&&`, `\|\|` | Отрицание, И, ИЛИ |

```bash
case "$1" in
  start|run) echo "Запускаю" ;;
  stop)      echo "Останавливаю" ;;
  *)         echo "Использование: $0 {start|stop}" >&2; exit 2 ;;
esac

read -rp "Удалить каталог build? [y/N] " answer
if [[ "$answer" =~ ^[YyДд]$ ]]; then
  rm -rf -- ./build   # ⚠️ необратимо
fi
```

Проверяйте скрипты статическим анализатором [ShellCheck](https://www.shellcheck.net/) (`shellcheck script.sh`): он находит большинство ошибок из раздела «Частые ошибки».

## Git Bash в Windows

Git Bash — это Bash и набор GNU-утилит (MSYS2), которые ставятся вместе с Git for Windows. Он удобен для Git и простых скриптов, но это не полноценный Linux: нет `apt`, нет `sudo`, `ps` видит только свои процессы, права файлов эмулируются.

| Команда или приём | Назначение | Пример | Важные замечания |
|---|---|---|---|
| `/c/Users/...` | Формат путей | `cd /c/Users/Sergey/Documents` | `C:\Users\Sergey` в Git Bash выглядит как `/c/Users/Sergey`. Обратные слэши без кавычек «съедаются» |
| `cygpath` | Перевести путь между форматами | `cygpath -w ~` → `C:\Users\Sergey` | `cygpath -u 'C:\Windows'` → `/c/Windows` |
| Кавычки для путей | Пробелы и кириллица в пути | `cd "/c/Users/Sergey/Мои документы"` | Кириллица работает, но пробелы без кавычек разбивают путь на части |
| `explorer .` / `start .` | Открыть текущий каталог в Проводнике | `explorer .` | `start файл.pdf` откроет файл программой по умолчанию |
| `clip` | Скопировать в буфер обмена | `cat ~/.ssh/id_ed25519.pub \| clip` | Вставка из буфера в терминал — `Shift+Insert` |
| `winpty` | Запуск интерактивных консольных программ | `winpty python` | Нужен, если REPL или `docker exec -it` «зависает» без приглашения. В новых версиях Git for Windows обычно не требуется |
| `MSYS_NO_PATHCONV=1` | Отключить автоматическую подмену путей | `MSYS_NO_PATHCONV=1 docker run --rm alpine ls /` | Git Bash превращает аргументы вида `/app` в `C:/Program Files/Git/app`. Альтернатива — двойной слэш: `//app` |
| `tasklist` / `taskkill` | Процессы Windows | `taskkill //PID 1234 //F` | Слэши удвоены из-за подмены путей. ⚠️ **Опасно:** `//F` убивает процесс принудительно |
| `netstat -ano` | Кто слушает порт | `netstat -ano \| grep :8000` | Последняя колонка — PID; имя процесса: `tasklist //FI "PID eq 1234"` |
| `py` / `python` | Запуск Python | `py -3 --version` | `python3` может открыть Microsoft Store. Отключите псевдонимы в «Параметры → Приложения → Псевдонимы выполнения приложений» |
| `dos2unix` | Убрать CRLF из скрипта | `dos2unix deploy.sh` | Без него: `sed -i 's/\r$//' deploy.sh` (⚠️ правка на месте). Надёжная профилактика — `.gitattributes` с `*.sh text eol=lf` |
| `git update-index --chmod=+x` | Сохранить бит исполнения в Git | `git update-index --chmod=+x deploy.sh` | NTFS не хранит права Unix, поэтому `chmod +x` в Git Bash в репозиторий не попадёт |
| `~/.bashrc` и `~/.bash_profile` | Настройки оболочки | `echo "alias ll='ls -lah'" >> ~/.bashrc` | Git Bash стартует как login-shell и читает `~/.bash_profile`. В нём должна быть строка `source ~/.bashrc` |
| `cmd //c` | Выполнить команду cmd | `cmd //c ver` | Для PowerShell: `powershell -NoProfile -Command "Get-Date"` |
| `LANG` | Локаль для работы с кириллицей | `export LANG=ru_RU.UTF-8` в `~/.bashrc` | Если Git Bash запущен не из своего окна (из PowerShell, IDE, планировщика), `LANG` бывает пустым. Тогда `${#s}` считает байты, а не буквы, регулярные выражения с кириллицей не совпадают, а `${s^^}` может завершиться ошибкой `Segmentation fault`. Проверка: `locale` |

Проверка, что вы именно в Git Bash: `uname -s` выводит `MINGW64_NT-...`, в WSL — `Linux`.

> [!NOTE]
> Если в PowerShell или cmd набрать `bash`, запустится **WSL**, а не Git Bash. Если дистрибутив WSL не установлен, появится ошибка вида `execvpe(/bin/bash) failed`. Чтобы запустить скрипт в Git Bash из PowerShell, вызовите его явно: `& "C:\Program Files\Git\bin\bash.exe" script.sh`.

## WSL

WSL (Windows Subsystem for Linux) запускает настоящий Linux внутри Windows. Если нужны `apt`, `sudo`, `systemd`, полноценные права и максимальная совместимость с серверами — выбирайте WSL, а не Git Bash.

Команды управления выполняются в **PowerShell** или **cmd** Windows:

| Команда | Назначение | Пример | Важные замечания |
|---|---|---|---|
| `wsl --install` | Установить WSL и Ubuntu по умолчанию | `wsl --install` | Нужны права администратора и, как правило, перезагрузка |
| `wsl --list --online` | Доступные для установки дистрибутивы | `wsl -l -o` | |
| `wsl --install -d ИМЯ` | Установить конкретный дистрибутив | `wsl --install -d Debian` | |
| `wsl -l -v` | Установленные дистрибутивы, их состояние и версия WSL | `wsl -l -v` | Рабочий вариант — `VERSION 2` |
| `wsl -d ИМЯ` | Открыть оболочку дистрибутива | `wsl -d Ubuntu` | Просто `wsl` открывает дистрибутив по умолчанию |
| `wsl --set-default ИМЯ` | Дистрибутив по умолчанию | `wsl -s Ubuntu` | |
| `wsl -- КОМАНДА` | Выполнить одну Linux-команду из Windows | `wsl -- ls -la ~` | |
| `wsl --shutdown` | Остановить все дистрибутивы и виртуальную машину | `wsl --shutdown` | Помогает после изменения `.wslconfig` или при «зависании» сети |
| `wsl --terminate ИМЯ` | Остановить один дистрибутив | `wsl -t Ubuntu` | Несохранённая работа в его процессах будет потеряна |
| `wsl --update` / `wsl --status` | Обновить WSL / показать версию и настройки | `wsl --update` | |
| `wsl --export` | Резервная копия дистрибутива в tar | `wsl --export Ubuntu D:\backup\ubuntu.tar` | Делайте перед экспериментами и переустановкой |
| `wsl --import` | Восстановить или клонировать дистрибутив | `wsl --import Ubuntu2 D:\wsl\ubuntu2 D:\backup\ubuntu.tar` | |
| `wsl --unregister ИМЯ` | Удалить дистрибутив | `wsl --unregister Ubuntu` | ⚠️ **Опасно:** безвозвратно удаляет весь диск дистрибутива — все файлы в `/home`, базы и настройки. Сначала `wsl --export` |

Внутри WSL:

| Команда | Назначение | Пример | Важные замечания |
|---|---|---|---|
| `/mnt/c/...` | Доступ к дискам Windows | `cd /mnt/c/Users/Sergey/Documents` | Работа с файлами через `/mnt/c` в разы медленнее, чем в `~`. Держите проекты в файловой системе Linux |
| `\\wsl.localhost\ИМЯ` | Файлы Linux из Проводника Windows | `\\wsl.localhost\Ubuntu\home\sergey` | На старых сборках путь начинается с `\\wsl$\` |
| `explorer.exe .` | Открыть текущий каталог Linux в Проводнике | `explorer.exe .` | Из WSL можно запускать любые `.exe` |
| `code .` | Открыть проект в VS Code или Cursor через Remote-WSL | `code .` | Редактор работает с файлами Linux напрямую, без медленного `/mnt/c` |
| `wslpath` | Перевести путь | `wslpath -w ~` / `wslpath -u 'C:\Users'` | Аналог `cygpath` из Git Bash |
| `sudo apt update && sudo apt upgrade` | Обновить пакеты (Ubuntu/Debian) | `sudo apt install -y build-essential` | В WSL это обычный Linux |
| `cat /etc/os-release` | Какой дистрибутив и версия | `cat /etc/os-release` | |
| `ip addr` / `hostname -I` | IP-адрес WSL | `hostname -I` | Сервер, слушающий `0.0.0.0` в WSL, обычно доступен из Windows как `localhost:ПОРТ` |

Особенности WSL, о которых стоит помнить:

- Git в WSL и Git в Windows — разные установки с разными `~/.gitconfig`. Настройте `user.name` и `user.email` в обоих. Чтобы не вводить пароль, в WSL можно подключить Git Credential Manager из Windows (см. документацию WSL в [SOURCES.md](../SOURCES.md)).
- Если один и тот же репозиторий открыт и из Windows, и из WSL, будут проблемы с окончаниями строк и правами файлов. Выберите одну сторону.
- Docker Desktop интегрируется с WSL: в настройках *Resources → WSL Integration* включите нужный дистрибутив, и `docker` заработает внутри него.
- Ограничить память и процессоры WSL можно в файле `%UserProfile%\.wslconfig` (раздел `[wsl2]`, ключи `memory=` и `processors=`). После изменений выполните `wsl --shutdown`.

## Практические сценарии

**1. Безопасно удалить старые логи.** Сначала смотрим, что попадёт под удаление, и только потом удаляем.

```bash
find ./logs -type f -name "*.log" -mtime +14 -print        # 1. проверка
find ./logs -type f -name "*.log" -mtime +14 -delete       # 2. ⚠️ удаление без возврата
```

**2. Найти, что занимает место.**

```bash
du -ah . 2>/dev/null | sort -rh | head -n 10      # 10 самых больших файлов и каталогов
du -h --max-depth=1 . | sort -rh                   # размеры подкаталогов первого уровня
```

**3. Заменить текст во многих файлах с резервными копиями.**

```bash
grep -rlZ --include="*.yml" "old-host" . | xargs -0 sed -i.bak 's/old-host/new-host/g'
grep -rn "new-host" --include="*.yml" .        # проверяем результат
find . -name "*.yml.bak" -print                 # копии можно удалить после проверки
```

**4. Обработать файлы с пробелами в именах.**

```bash
find . -type f -name "*.txt" -print0 |
  while IFS= read -r -d '' file; do
    printf '%5d %s\n' "$(wc -l < "$file")" "$file"
  done
```

**5. Сохранить полный вывод долгой команды и видеть его на экране.**

```bash
./build.sh 2>&1 | tee "build-$(date +%Y%m%d-%H%M%S).log"
```

**6. Проверить зависимости в начале скрипта.**

```bash
for cmd in git docker curl; do
  command -v "$cmd" >/dev/null 2>&1 || { echo "Не найдено: $cmd" >&2; exit 1; }
done
```

**7. Сделать резервную копию каталога перед рискованной операцией.** Используйте [`examples/bash/backup_dir.sh`](../examples/bash/backup_dir.sh):

```bash
bash examples/bash/backup_dir.sh ./project ./backups
tar -tzf backups/project-*.tar.gz | head     # убедиться, что архив читается
```

**8. Найти процесс, занявший порт, и остановить его.**

```bash
# Linux / WSL
ss -ltnp | grep ':8000'          # или: lsof -i :8000
kill <PID>                       # сначала вежливо; kill -9 — только если не помогло

# Git Bash в Windows
netstat -ano | grep ':8000'
taskkill //PID <PID>
```

## Частые ошибки

| Ошибка | Что происходит | Как правильно |
|---|---|---|
| `name = "x"` | `name: command not found`: Bash ищет команду `name` | `name="x"`, без пробелов вокруг `=` |
| `rm -rf $DIR/` при пустой `DIR` | ⚠️ Превращается в `rm -rf /` | `rm -rf -- "${DIR:?}/"` |
| Переменные без кавычек: `cp $src $dst` | Пути с пробелами разбиваются на части, `*` раскрывается как glob | `cp -- "$src" "$dst"` |
| `sort file > file` | ⚠️ Файл обнуляется до чтения, данные потеряны | `sort file > file.tmp && mv file.tmp file` или `sort -o file file` |
| `uniq` без `sort` | Дубликаты, стоящие не рядом, остаются | `sort \| uniq` или `sort -u` |
| `cd dir` в скрипте без проверки | При ошибке `cd` следующие команды выполнятся в другом каталоге | `cd dir \|\| exit 1` или `set -e` |
| `[ $a == $b ]` с пустой переменной | `[: ==: unary operator expected` | `[[ "$a" == "$b" ]]` |
| `$'\r': command not found` | Скрипт сохранён с окончаниями строк Windows (CRLF) | `dos2unix script.sh`, в редакторе выбрать LF, добавить `.gitattributes` |
| `((count++))` при `set -e` | Когда `count` равен 0, выражение возвращает код 1, и скрипт тихо завершается | `count=$((count + 1))` |
| `cat file \| while read ...; do total=...; done` | Цикл выполняется в подоболочке, и после него переменная пуста | `while ...; done < file` |
| `"~/projects"` в кавычках | Тильда в кавычках не раскрывается: ищется каталог с именем `~` | `~/projects` без кавычек или `"$HOME/projects"` |
| `for f in $(ls *.txt)` | Ломается на пробелах. Разбирать вывод `ls` вообще не стоит | `for f in *.txt` |
| `echo $PATH` после `export PATH=...` в другом окне | Каждый терминал — отдельный процесс со своим окружением | Добавить в `~/.bashrc`, выполнить `source ~/.bashrc` |
| `./script.sh: Permission denied` | У файла нет права на выполнение | `chmod +x script.sh` или `bash script.sh` |
| `bash` в PowerShell выдаёт ошибку WSL | `bash.exe` в `PATH` — это WSL, а не Git Bash | Запускать `C:\Program Files\Git\bin\bash.exe` или установить дистрибутив WSL |
| `${#s}` для `"привет"` выдаёт 12, кириллица в `[[ =~ ]]` не находится | Не задана UTF-8-локаль, и Bash работает с байтами | `export LANG=ru_RU.UTF-8` (или `en_US.UTF-8`), проверить командой `locale` |
| Работа в WSL в `/mnt/c/...` | Сборка и `git status` работают очень медленно | Хранить проект в `~` внутри WSL |
